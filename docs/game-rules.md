# ゲームルール

## 目的と進行

ロボットが施設の最深部から一本道を進み、15マス目のイベントを電力を残して解決すると脱出成功です。サイコロ移動、戦闘、電力以外の消耗資源はありません。

ゲーム開始時の状態は位置1、電力20 / 最大20、進行中です。マスに入るたびイベントが1つ抽選され、2〜3個の行動から1つを実行します。解決後、電力が残っていれば次のマスへ進みます。電力は成功・失敗時の差分を適用して0〜20に収めます。上限を超えた分は捨てられ、下限に達した場合は0です。

行動を選んだ後は、表示中のスロット数字00〜99を停止数字として確定します。表示成功率を `p`、停止数字を `n` とすると、`n < p` の場合に成功し、それ以外は失敗です。成功率は選択肢に表示した整数をそのまま使います。結果を確定する順序は次のとおりです。

1. 停止数字と表示成功率を厳密な未満で比較し、成功差分または失敗差分を電力へ適用する。
2. 電力が0なら位置を進めずゲームオーバーにする。
3. 電力が残っていて、解決したマスが15なら脱出成功にする。
4. 成功・失敗のどちらでも、次のマスのイベントを一度だけ抽選して保留する。
5. 結果表示が終わった後、プレイヤーの進行操作で位置・現在イベントを更新する。

成功・失敗後の待機中は電力と履歴に結果を反映しますが、位置と現在イベントは解決したマスのままです。次イベントの抽選はスロット結果確定時に一度だけ行うため、待機時間や入力回数で乱数列は変わりません。結果表示が終わった後、画面タップまたはPCのクリック・`Space`・`Enter`で次へ進みます。文字送り中の操作は表示のスキップにだけ使います。

したがって最終マスで電力が0になった場合も失敗です。終了後の行動は無効です。終了画面から新しいランを開始できます。

## 区画

15マスを5マスずつ3区画に分けます。マス1〜5は区画1、6〜10は区画2、11〜15は区画3です。各区画は開始時に「安定」または「劣化」の状態を独立に受け取り、区画を出るまで変化しません。

区画の状態は画面、イベント説明、ログには直接記録しません。同一区画の複数マスに現れる不完全な観測から推測します。成功・失敗は表示率とスロット数字だけで決まり、設備状態の証拠にはなりません。

## 選択肢の電力表示

選択前に各行動の整数成功率と成功・失敗時の電力差分を示します。成功率は観測から推定し、100倍して四捨五入した値です。スロットもこの値を閾値として使い、表示が65%なら00〜64が成功、65〜99が失敗です。電力上限・下限を超える場合は、実際に適用される差分を表示します。たとえば電力19で成功時に+5の行動なら、表示は+1です。

### 状態とUIの分離

`src/game.ts` の内部状態には区画状態が含まれます。画面は `toGameView()` の投影だけを使い、画面向けデータに含める成功率は表示用の整数だけです。区画状態、丸める前の確率、乱数はDOMへ出力しません。イベント履歴には場所、観測文、選択、確定結果、電力の前後を記録します。
