# 移動・描画仕様

3D表示と操作を確認するサンプル。敵・感覚・ターン制は[enemy-ai.md](enemy-ai.md)を参照。持ち物は閲覧用マップだけで、クリア判定はない。ゲームロジックと描画は維持し、入力UIのみ階層コマンドへ変更する。

## マップと境界

src/dungeon.tsのDUNGEON_MAPは16行×16列。#は床、半角スペースは通行不可。床は112マス、外周はすべて通行不可。

以下は両端の `|` を列境界として示す（`|` はマップデータに含めない）。各行の内部は半角16文字。

```text
|                |
| ####     ##### |
| #### ######### |
| ####  #  ##### |
|  #    #  ##### |
|  ###########   |
|  #   ###   #   |
|  #   ###   #   |
| #### ###   #   |
| ####  #    #   |
| ####  #  ##### |
| ############## |
|  #       ##### |
|  #       ##### |
|  #           # |
|                |
```

左上が原点、Xは右、Yは下。初期位置は(2,14)、北向き。北へ3マスで分岐(2,11)に到達し、「調べる→扉→はい」で正面の扉を通過すると南西の部屋(2,10)へ入る。facingは北0・東1・南2・西3。

北西（X=1〜4、Y=1〜3）、北東（X=10〜14、Y=1〜4）、中央（X=6〜8、Y=6〜8）、南西（X=1〜4、Y=8〜10）、南東（X=10〜14、Y=10〜13）の5部屋を通路で接続する。曲がり角、T字路、(7,2)付近の分岐、(6,2)・(2,14)・(14,14)の行き止まりがあり、中央の部屋を経由する道と東側の通路を回る迂回路を持つ。北西の部屋へは扉通過が必要。

DOORSは床セルとは別の境界情報で、6か所ある。

| from（通路側） | to（部屋側） |
| --- | --- |
| (2,11) | (2,10) |
| (2,4) | (2,3) |
| (9,2) | (10,2) |
| (12,5) | (12,4) |
| (7,5) | (7,6) |
| (12,9) | (12,10) |

doorBetweenは両方向から境界を判定する。すべて隣接する床マス間の境界で、重複はない。扉の開閉状態、タイマー、アニメーションは持たない。別マップには扉配列を明示的に渡せる。

「移動→前進」はmoveのup、「左を向く／右を向く／後ろを向く」はleft／right／downに対応する。前進は1マス、回転は座標を変えず90°左／90°右／180°。床以外・マップ外・扉境界は前進不可。「調べる→扉」は正面に有効な扉がある場合だけ表示し、0ターンの確認を出す。「はい」は独立回答として確定し、実行直前に再確認してpassDoorで隣接床へ移動する。向きは維持し、常に閉じた扉として描画する。「いいえ」は移動しない。いずれも通常メニューへ戻る。内部advanceTurnの'a'は既存扉処理の識別子として維持するが、Aボタンは存在しない。

前進成功・左右90度・180度回転・扉通過成功は各1ターン。失敗前進は0ターンで警告のみ。プレイヤー・敵・検知・訪問履歴は保持し、敵AI・感覚再判定・音生成・新たな捕獲判定を行わない。メニュー・戻る・扉確認・いいえ・マップ操作は0ターン。ゲームオーバー後もログ、マップ、言語は操作可能。

## 描画

src/renderer.tsは閉じた境界を越えずに現在位置から到達できる床領域を抽出し、その壁境界と扉境界を求め、プレイヤーの座標・向きからカメラ座標へ変換する。壁面の平面で空間を分割するBSPにより、カメラから遠い側から手前へ描く。近クリップ面で切り取り、x/z、y/zで透視投影する。壁面をダンジョン背景色で塗り、緑色の輪郭線を描くことで奥の線を遮蔽する。正面壁、左右壁、閉じた扉の裏側は見えず、床同士の開口部には壁面を置かないため、実際に見える左右通路は表示される。特定のT字路に依存しない共通処理。

扉は壁面に長方形の枠、内部の横線、取っ手を描く。境界は一度だけ描画し、どちらの側からも同じ閉じた扉が見える。扉通過の移動直後にmain.tsが移動先のSVGを更新する。外部3Dライブラリは使用しない。

main.tsは入力、画面更新、言語メニュー、ログ追加を担当する。描画座標は移動判定に使わない。

## ログと検証

初期・失敗警告・扉通過・敵検知・捕獲はGameState.logsのイベントとして維持する。通常の成功移動・回転は追加説明を出さず、UIの構造化コマンド履歴へ残す。コマンド→イベント→新しい > の順で描画し、言語切替で全履歴を再翻訳する。入力途中は確定履歴と分離する。詳細なメニュー・扉確認・履歴構造は[ui-layout.md](ui-layout.md)を参照。

npm testは16×16マップ、112床／448状態の到達、扉境界、描画、ターン・敵AI・感覚、固定メニュー枠とコマンド翻訳を検証する。npm run buildは型検査と配布ビルド。npm run test:browserは日英コマンドUI、全112床のタップ探索、扉往復といいえ、失敗警告、時系列履歴・言語切替、マップ状態保持・外周制限・再表示、敵検知マーカー、固定方角欄、320px／1280px、短い画面と模擬Safe Area、3D壁遮蔽と開口部を検証する。旧方向ボタン・A/B・矢印キーの操作経路は使用しない。本番にテスト専用APIは追加しない。

実機iOS Safari／Android Chromeと実際のノッチ・ブラウザバーの変化は未検証。

### 3D描画時間の確認

同一環境のNode.jsで、全床×4方向を3周ウォームアップ後に10周計測した。旧5×5は360回、新16×16は4480回。renderDungeonの中央値は旧0.018ms／新0.253ms、95パーセンタイルは旧0.103ms／新0.457ms、新マップの最大は2.751msだった。床増加によって処理時間は増えるが、この環境では1回あたり1ms未満（95%）に収まる。SVG生成のみの計測で、実機ブラウザの描画時間を保証するものではない。

## 2Dオートマップ

初期表示は3D。「持ち物→マップ」で同じ枠を2Dへ切り替え、「閉じる」で戻る。既存の表示枠、ログ、操作部の配置と方角ラベルは維持する。右側の固定ステータス欄も配置・内容を維持する。

src/automap.tsは3D描画から独立する。訪問履歴は既存座標の文字列キー（x,y）のSetで管理し、初期位置だけを登録する。通常移動・扉通過によって座標が変化したときだけ移動先を追加する。回転・移動失敗・切替は追加しない。再訪は重複せず、履歴は表示切替後も保持する。再読み込み時の保存は行わない。

DUNGEON_MAPの訪問済み床のみを24×24（SVG座標）の正方形で描画する。SVGのviewBoxは320×200のまま、未探索領域と空間は黒（#000）、訪問済み床は暗い緑（#123c24）とする。各マスの枠線は描かず、つながる床を連続して表示する。現在位置は明るめの床（#245c38）と白緑（#e5fff0）の方向矢印で示す。矢印は幅12・高さ14の図形を中心で回転し、24×24のマス内に収める。北は上、東は右。表示中心はプレイヤー・訪問履歴とは独立したワールド座標で管理する。マップを開くたび現在のプレイヤー位置を基準に初期化し、ダンジョン全体の寸法で制限する。表示枠より小さい軸はダンジョン中央に固定する。大きい軸は表示枠が外周を越えない範囲で中心を制限する。マップサイズは行数・最大列数から取得する。範囲外のセルは省略し、履歴は保持する。

訪問済み床の北・東・南・西をisFloorで独立判定し、通行不可またはマップ外の境界だけに明るい緑（#4ade80）、幅2の実線を描く。通行可能な隣接床は未訪問でも壁線を描かず、その未訪問床自体も表示しない。DOORSとdoorBetweenで訪問済み床に接する扉を判定し、境界中央に隙間のある平行二重線で表す。扉境界には通常の壁線を重ねない。境界中央のワールド座標で重複を排除し、両側から同じ位置・向きに表示する。通過後も扉情報は保持する。未訪問床自体の輪郭や遠方の壁・扉は描かない。

マップ中は上／下／左／右でscrollMapにより中心を北／南／西／東へ1マス更新する。外周では制限する。開く・上下左右・閉じるはHistoryEntryを追加せず、確定済みログとスクロール位置を保持する。持ち物選択の入力途中はマップを開く際に破棄し、表示中と閉じた後は > を表示する。位置・向き・ターン・敵・検知・訪問履歴は不変。左下の「閉じる」は通常メニューと3Dへ戻す。言語変更で中心は保持し、再表示時はプレイヤー位置から初期化する。

## 検知した敵の2D表示

GameState.detectionsは敵IDを付けたSight／Hearingの現在ターンのスナップショット。初期は空で、敵行動後のプレイヤー感覚判定で毎ターン全件を置き換える。同時成立は視覚のみ保持し、検知できなかった敵は除外する。ログ履歴や敵AIの実座標・向きから表示情報を補完しない。視覚の向きを次の聴覚検知へ引き継がない。

視覚は検知座標に淡い赤（#fb7185）の方向矢印を表示する。敵自身の絶対方角（北=上、東=右、南=下、西=左）を使い、プレイヤーと同じ幅12・高さ14のSVG図形とする。聴覚のみは音源座標に半径7・線幅2の同色の○を表示し、方向の装飾は付けない。いずれも24×24マス内に収まる。白緑（#e5fff0）のプレイヤー矢印は変更せず最後に描き、重なった場合も視認性を保つ。新しいUI領域や凡例は追加しない。

未訪問マスでも検知マーカーだけは表示し、床・壁・扉は公開しない。既存のマップ座標変換と320×200のviewBoxを使い、中心が表示範囲外のマーカーは省略、端はSVGでクリップする。スクロールで範囲内に戻れば保持中の同じ検知状態で表示する。

最後に完了したターンの検知結果を次のゲームターンまで保持する。前進失敗、コマンドによる3D／2D切替、マップスクロール、言語切替、メニュー操作では敵行動も再判定も行わない。3Dで得た検知結果も2Dへ切り替えた際に表示する。捕獲ルールは維持し、プレイヤーが敵へ入った場合はそのターンの検知を空にして直ちに終了する。敵がプレイヤーへ入った場合は既存どおりそのターンの感覚判定を完了する。ゲームオーバー後は敵と検知状態を更新しない。

選択肢は2列×3行で1ページ6枠。下の操作行の左端に独立した戻る（72×44px）、中央にページナビゲーションを置く。全メニューで番号を表示し、メニュー遷移で先頭へ戻す。マップは1 / 1、両矢印と戻るは無効。「閉じる」は選択肢の左下に残す。詳細は[ui-layout.md](ui-layout.md)。
