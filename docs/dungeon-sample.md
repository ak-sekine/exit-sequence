# 移動・描画仕様

これは3D表示と操作を確認するサンプル。敵、アイテム、イベント、クリア判定はない。

## マップと状態

src/dungeon.tsのDUNGEON_MAPは以下の4行×5列。#が床、半角スペースは通行不可。

```text
#####
  #  
  #  
  #  
```

左上が原点、Xは右、Yは下。初期状態は(2,3)、北。facingは北0・東1・南2・西3。上は向いている方向に1マス前進、左／右／下は座標を変えず90°左／90°右／180°回転。床以外とマップ外へは移動しない。moveはDOMに依存せず新しい状態とログキーを返す。

## 描画

src/renderer.tsのrenderDungeonは同じマップと現在状態からSVGを生成する。セル中心にカメラを置き、前方向と右方向を向きから求める。壁・床・天井の境界点をカメラ座標へ変換し、x/z、y/zで透視投影する。直進方向は現在セルを含む最大4セルで、最初の正面壁で打ち切る。左右が床なら側面壁を省略し、分岐の床・天井の線を最大4セル先まで伸ばす。分岐の終端が見える範囲にあれば終端壁も描く。塗りつぶし・テクスチャ・外部3Dライブラリは使わない。一般的な3Dエンジンや任意形状の完全な可視判定ではなく、グリッド通路の簡易描画。

描画座標は移動判定に使わない。マップ交換後も同じ移動・描画関数を使用できる。main.tsは入力、状態保持、言語メニュー、ログ追加を担当する。

## ログ

初期「通路にいる。」、成功「前進した。」、左「左を向いた。」、右「右を向いた。」、下「後ろを向いた。」、不可「これ以上進めない。」。すべて英語訳を持つ。前進不可でもログを追加する。A・Bでは追加しない。

## 検証

npm testで初期状態、北へ3マス、T字路での前進不可、西へ2マス、端での停止、180°回転、右4回転、別マップ、正面壁と左右開口部、翻訳を確認する。npm run test:browserはViteサーバー起動後に実行し、日本語／英語、タップ、A・B、表示変化、言語メニュー、ログ追従、320px幅の640／480／320／240px高さ、模擬Safe AreaをChromiumで確認する。npm run buildで型検査と配布ビルドを行う。

実機のiOS Safari／Android Chrome、実際のノッチ・ブラウザバーの変化は別途確認が必要。
