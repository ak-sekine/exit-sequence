# バランス測定

確率固定化で同一行動の成功率が区画や観測履歴に左右されなくなりました。成功率は従来の基準成功率を整数化し、行動ごとの電力差分は維持しています。安定・劣化の補正は削除しています。

`npm run simulate` は12,000試行ずつ、乱択・常に1番・失敗損失最小・成功回復最大・固定確率と生存重視の5方針を比較します。シミュレーターは行動結果後に `continueAfterResult()` を呼び、終了まで進行させます。

## 測定結果

共通シード12,000件で旧仕様を比較した際も、旧版シミュレーターの保留イベント処理を直して最後まで進行させました。

| 方針 | 旧ルール | 固定率ルール |
|---|---:|---:|
| 乱択 | 30.5% | 30.4% |
| 常に1番 | 57.5% | 59.7% |
| 失敗損失最小 | 79.0% | 78.8% |
| 成功回復最大 | 9.1% | 8.0% |
| 生存重視 | 87.7% | 86.2% |

固定率化後も差は小さく、慎重な方針と高リターン狙いで結果が分かれます。成功回復最大方針は大きな電力回復を狙って低確率・大損失の選択を取りやすく、リスクが明確です。成功率は元の基準成功率を整数化した値のままで、バランス目的の変更は加えていません。
