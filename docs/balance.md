# バランス測定

確率固定化で同一行動の成功率が区画や観測履歴に左右されなくなりました。成功率は従来の基準成功率を整数化し、行動ごとの電力差分は維持しています。安定・劣化の補正は削除しています。

`npm run simulate` は12,000試行ずつ、乱択・常に1番・失敗損失最小・成功回復最大・固定確率と生存重視の5方針を比較します。シミュレーターは行動結果後に `continueAfterResult()` を呼び、終了まで進行させます。

## 測定結果

共通シード12,000件で旧仕様を比較した際も、旧版シミュレーターの保留イベント処理を直して最後まで進行させました。

| 方針 | 旧ルール | 固定率ルール |
|---|---:|---:|
| 乱択 | 30.5% | 30.4% |
| 常に1番 | 57.5% | 59.7% |
| 失敗損失最小 | 79.0% | 78.8% |
| 成功回復最大 | 9.1% | 8.0% |
| 生存重視 | 87.7% | 86.2% |

固定率化後も差は小さく、慎重な方針と高リターン狙いで結果が分かれます。成功回復最大方針は大きな電力回復を狙って低確率・大損失の選択を取りやすく、リスクが明確です。成功率は元の基準成功率を整数化した値のままで、バランス目的の変更は加えていません。

## 100マス版

上記の数値は15マス版の測定結果であり、100マス版のクリア率や電力見通しを示さない。Phase 1の拡張サンプルは通常UIに接続せず、今回の基盤テストも100マス用電力バランス検証ではない。

Phase 5でシミュレーターを100マス対応にし、複数戦略ごとに以下を記録する。

- クリア率、平均到達距離、クリア時残電力、終端電力のP10/P50/P90。
- 1〜100の距離別平均電力と、GAME OVERが集中する区画。
- 連携成立/不成立ケース、アイテム未取得時、設備復旧失敗時、NPC未救出時。
- 旧15マスと新100マスは別々のテーブルと見出しで提示。

100マス版が公開候補になる完了条件は、少なくとも複数のseedで最後までシミュレーションし、全区画の電力推移をレビューしてから、本文/イラストを含む統合ビルドでも再測定すること。測定前の値は未検証として扱う。
