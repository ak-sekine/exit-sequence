# 物語設定

ロボットたちは感情豊かに暮らし、街には比較的安全な生活圏がある。街の外には長く使われていない廃墟や廃棄施設が点在し、かつて働いていたロボットたちの設備や部品が残る。危険なミュータントは以前から廃墟に多数生息しており、探索は危険な仕事だ。

主人公はスカベンジャーのロボット。好奇心旺盛で少し子どもっぽく、部品の値打ちを気にしながら廃墟を探る。前向きだが怖いものは怖い。失敗すると文句を言い、それでも街へ帰るために頑張る。

いつもの部品探しの最中に床が抜け、主人公は廃棄施設の最深部まで落ちた。限られた電力で設備を越え、ミュータントに会う前に地上へ脱出して、安全なロボットの街へ帰ることが目的。

現在の15マス版は旧仕様として、1〜5マスが廃棄物の多い最深部、6〜10マスが保守・搬送設備の中層、11〜15マスが外の光や風が近い上層。

100マス版は5区画を20マスずつ進む。1〜20は最深部、21〜40は廃棄物処理区画、41〜60は生産・整備区画、61〜80は管理・保守区画、81〜100は地上接続区画。短い説明と設備とのやり取りで、ロボットが働いていた施設の用途や、街へつながる経路を少しずつ伝える。区画1〜3の本文120件はPhase 3 P3-01〜03で実装したが、人による最終文章レビュー待ち。区画4・5は未着手で、100マスエンジンは通常起動へ接続しない。

CLEARでは地上へ出て街へ帰る喜びを描く。GAME OVERは電力切れによる一時停止として描き、主人公が充電器を呼ぶ。ミュータントとの戦闘や敵AIは登場しない。

## エンディング場面

最後の行動結果とエンディングを分けます。15マス目で電力が残れば、最後の行動が成功・失敗のどちらでも状態をCLEARに確定します。電力0ならそのマスでGAME OVERを確定します。プレイヤーが最後の行動結果を読み終えて「次へ進む ▶」を操作するまで、エンディングの見出し・画像・文章は表示しません。

CLEARの場面は `[CLEAR]`、`public/story/clear.png`、専用文章の順にログへ追加します。画像は施設の出口から主人公が勢いよく飛び出して喜ぶ320×200のマンガ調イラストです。文章は「地上の光だ！ 出口だ！」「やった、ぼく生きてる！」「拾った部品？」「……あれ、どこに置いたっけ。」「まあいいや、街へ帰ろう！」です。

GAME OVERの場面は `[GAME OVER]`、`public/story/game-over.png`、専用文章の順にログへ追加します。画像は暗い廃棄施設の通路でへたり込む同じロボットを描いた320×200のマンガ調イラストです。目の光を弱々しくし、充電器を求めるコミカルな場面にします。電力切れは停止であり死亡ではありません。文章は「あれ？ 体が動かない。」「どうやら電力がゼロになったらしい。」「ぼくの冒険はここまで。」「誰か、充電器を持ってきてー！」です。

ストーリー画像の主人公は、大きな装甲頭部と表示顔、短いアンテナ、関節の見える手足、回収袋を共通の目印にします。プロローグは割れた床から落下する場面、CLEARは出口から飛び出す場面、GAME OVERは通路でへたり込む場面です。黒地に緑色だけの手描きマンガ調で、小さい表示でも表情と動作が分かるようにします。画風の詳細は[画像制作仕様](art-style.md)を参照してください。

エンディング画像は見出し直後に即時表示し、文章だけ10ms/文字で送ります。320×200のPNGを最大幅320px・8:5で表示し、読み込み前から寸法を確保します。画像・文章はログ履歴に残り、画像読み込み失敗時も文章と操作は続きます。全文表示が終わってから再スタート操作を表示します。

## NPC設定と再登場ルール

ロボットNPCは感情豊かで、それぞれ固有の名前、外見上の特徴、性格、話し方を持つ。初期目標は約10体、1体あたり2〜3イベント。NPCの初登場・救出・再会はそれぞれ別イベントIDを使い、同一イベントIDの重複防止とは別にNPCの同一性を管理する。

Phase 1の連携確認用NPCはモモ。片耳のように曲がったアンテナと丸い作業アームが目印で、心配性だが親切。小声で語尾に「かも」を付ける。状態は `unmet` から初登場時の `rescued`、`rescue-failed`、`encountered` に分かれる。再会後は `repaid`。救出済みの場合だけ上層で再会し、助けてもらったことを明示して恩返しする。未遭遇・救出失敗・見送りの状態では、再会や恩返しの台詞を候補にしない。

`src/expansion-engine.ts` のNPC定義と `src/expansion-content/zone1.ts` のモモ、ノリ、ゴロ、チリ初登場は拡張データ用。Phase 2では [NPC設定カタログ](npc-catalog.md) と [イベント台帳](event-catalog.md) に10体の外見・性格・話し方、初登場・再会、救出状態を確定した。各NPCは初登場と後続区画での再会の2イベントで構成する。再会イベント本文は後続バッチで制作する。100マス用データは未接続であり、実行中の15マス版へ追加しない。

## 100マス版の物語進行

100マス版では主人公が最深部から地上へ向かい、20マスごとに施設の用途が分かっていく。ここで示すのは拡張版の構成で、現行15マス版の区画や進行は変更しない。

| 距離 | 区画 | 物語上の役割 |
|---|---|---|
| 1〜20 | 最深部 | 落下直後の混乱と廃材探索。暗い空洞や古い作業場所を抜け、鍵、警報線図、紙の換気模型など、上への手掛かりを拾う。ロボットNPCとの最初の出会いもここから始まる。 |
| 21〜40 | 廃棄物処理区画 | 分別帯、圧縮機、洗浄排水、気送管など施設が廃棄物を処理していた様子が分かる。警報停止はミュータントとの戦闘を起こさず、音を抑えて危険な気配を避ける手段として描く。 |
| 41〜60 | 生産・整備区画 | 部品の組立、検査、塗装、冷却を担った区画。廃棄物区画から持ち込んだ規格部品や情報が設備を直す理由となり、施設内の仕事のつながりが見える。 |
| 61〜80 | 管理・保守区画 | 点検記録、古い認証、制御盤、保守シャフトが並ぶ。前区画で記録した情報や復旧した設備を使い、地上へ向かう昇降路と送風路を準備する。救出したNPCの再会も起きる。 |
| 81〜100 | 地上接続区画 | 外の風、光、葉、街の音が段階的に近づく。最後の扉や昇降路には手動の迂回路を残し、電力が残っていれば結果が成功・失敗いずれでも100マス目でCLEARとなる。 |

複数区画にまたがる主な因果は、保守鍵→廃棄ハッチ、警報線図→静音経路、紙の換気模型→換気シャッターと管理盤、予備電源または規格ヒューズ→保守昇降機、工程カードと型番コード→管理端末、点検シャフトの安全爪→上層の補助柵である。各効果は設備番号・形状・同じ配管などの観察可能な根拠を持たせる。条件を得られなくても通常候補だけで先へ進める。

10体のNPCは初回の救出や会話を覚えており、条件が成立した場合だけ後続区画で再会する。助けられなかったNPCが感謝を述べたり、救出済みを前提に話したりしない。後続での効果は案内や視認性、安全な足場、小さな恩返しなどで、毎回の成功率上昇や充電に限定しない。各IDと状態条件は [依存関係表](event-dependencies.md) に記録する。

## イベントの文章作成ルール

### イベント説明文

- 主人公の視点を中心にし、状況・設備・選べる行動が自然に伝わるようにする。
- 感情豊かなロボットだけが暮らす世界観に合わせ、明るくコミカルな文体を保つ。
- 説明を長くしすぎず、行動選択に必要な情報を短く伝える。

### 成功文

- 選んだ行動が成功したと分かる描写にする。
- 描写と実際の電力変化を一致させる。成功時にも電力を消費する行動があるため、「成功＝充電」と決めつけない。
- 主人公の喜びや反応を表し、短く読みやすくする。

### 失敗文

- 選んだ手段で期待した結果を得られなかったことを明確にする。失敗は必ずしも移動失敗を意味しない。
- 電力の増減と描写を一致させる。電力を失う結果なら消耗が伝わる表現にする。
- 電力が残っている失敗後も次のマスへ進めるルールと矛盾させない。障害物の突破に失敗した場合も、別経路や別の通過方法があり得ると伝わるようにする。
- 失敗文だけで完全に進行不能、永久に足止め、脱出済みと確定させない。失敗直後に次の場所へ移動したと断定しない。
- 電力が0になってGAME OVERとなる場合にも成立させる。移動継続を断定せず、可能性や探索の余地として描く。
- 過度に悲惨な描写を避け、主人公の感情とユーモアを入れる。同じ決まり文句を使い回さず、簡潔にする。
- 充電・回収の失敗は回収できなかった描写だけでもよい。設備に留まり続ける必要があるように書かない。

### 新イベント追加時のレビュー

新イベントは全行動について、成功文・失敗文、成功時と失敗時それぞれの電力差分との整合性、成功後と失敗後の次イベントへの接続、電力0のGAME OVERとの整合性、コメディ調と世界観との整合性をレビューする。失敗文の意味は自動テストだけでは判定できないため、人による文章レビューを必須とする。イベント一覧のチェック項目は [イベント一覧](event-catalog.md) を参照。
