# Exit Sequence 文章スタイル（正本）

## 文章の役割

文章は装飾ではなく、現在の危険と行動方法を考える情報源。読む、現象を解釈する、行動を選ぶというループを支える。音の遠近、走査光の動き、消えない表示、呼吸、スーツの振動に意味を持たせる。危険の結果を突然後出しせず、行動前の描写とAIの補足から予測できるようにする。

## 主人公とAI

主人公の一人称は日本語「私」、英語 I / my。日本語では自然に主語を省略する。地の文は見えるもの、音、振動、光、空気、呼吸、スーツ、機械の動作、過去に得た知識からの認識のみ。主人公の知らない敵の意図・内部位置・未読ログは説明しない。

AIはセンサー結果、機械的警告、状態、装置情報、客観的補足を別段落で担当する。接頭辞は必ず日本語 `AI：`、英語 `AI:`。比喩や感情的な説明をAIに語らせない。観察をすべてシステム説明へ翻訳し尽くさない。

## 文体と長さ

静かでシリアスなSF。日本語は常体・短文・観察的な現在形を基本にする。動作の結果には自然な過去形を使える。英語は restrained, observational first-person prose, primarily present tense。直訳せず判断材料と警告を一致させる。名や性別・職業・年齢・性格を補完しない。過度な感情説明、長い比喩、大きな陰謀を加えない。

通常Sceneは2～4文程度、重要Sceneは必要なら5～7文程度を目安にし、短い段落に分ける。条件付き情報もスマートフォン320pxで読める長さにする。一度に文章の壁を出さない。

## Knowledgeで認識を変える

最初の「二本の黒い擦過痕」は見える事実だけ。映像を読んだ後には「あの映像と同じ痕だ。右側でロボットのアームが旋回した」と認識でき、低い陰を使う判断へ結びつく。知識は未取得の未来攻略を説明するカードではない。KNOWLEDGEには取得時に知った事実だけを載せる。

知識を読むChoiceでは、結果文章に実際に知った内容を示す。条件付き描写で新しい理解を加える。文章には未取得の知識を先回りして入れない。履歴は当時の認識を保存する。

## 状態を自然に描く

十分な酸素は一定の呼吸、少ない酸素はファンが耳につく、危険な酸素は薄い空気と点滅表示。負傷は左腕の弱さや痛み。脅威は遠い動作音、何度も近づく音、扉の外で止まる駆動音などで区別する。

同じ文を全Sceneへ機械的に足さない。装置前・気密室・船など、その判断に関係する場面で変化を描く。酸素をさらに使うと致命的になる段階は、描写と明確な警告で知らせる。

## Choiceも物語

「工具台へ」ではなく「試験札を読み、ネジを外して工具を持つ」。判断・意図・行動を文にする。音を出す、待つ、腕に力を込めるなどの代償を選択前に理解できるようにする。ボタンへ大量の数字を詰め込まない。使用条件を満たさない選択肢は表示しない。

ルール上必要な酸素段階、消耗品一回、暗闇無効、均圧の待機、先行点火の危険は曖昧にしない。AIとHELPで補足する一方、敵の場所などの数値表示に置き換えて読解を不要にしない。

## Endingと確認

OVERは表示消失や届かない空気で短く締め、過度に残酷にしない。CLEARは船の空気、遠ざかる基地、帰還航路を描く。終了ラベルは明示し、再開方法はUIに任せる。

日英で観察事実・警告・Knowledge・Item情報を一致させる。各文章ペアをレビューし、AI接頭辞、未取得情報の非開示、状態別描写、言語切替で進行しないことをテストする。主人公が知り得るか、描写が判断に役立つか、代償が予告されているかを文章追加ごとに確認する。
