# 画面レイアウトと操作

## 画面構成

スマートフォン縦画面を基準に、画面上部からタイトルとメニューボタン、正方形のゲーム表示、ステータス、直近のイベントログ、操作エリアを並べる。ゲーム表示は利用できる幅を使い、縦の空きが足りないときは縮小する。PCでは最大幅640pxで中央に配置し、横画面でも正方形を保つ。

`index.html` は `viewport-fit=cover` を指定する。アプリは上下左右の `safe-area-inset-*` を取り込み、ページ全体をスクロールさせない。ゲーム表示は黒背景の緑ワイヤーフレームと透過敵スプライトをCanvas 2Dで描き、内部解像度はdevicePixelRatioの最大2倍まで使う。マップ表示は同じ正方形領域のSVGを使う。

画面は次の情報だけを常時表示する。

- 方角は8方向、日本語と英語で表示する。
- 位置は現在のマップセル座標で示す。
- 部屋／通路は既存のサンプルマップ区分から表示する。
- 視覚または聴覚で敵を検知しているときだけ、検知状態を示す。
- イベントログは直近2件までにし、歩行や視点回転は記録しない。同じイベントは時間を空けて抑制する。

HP、弾薬、持ち物数のような未実装情報は表示しない。

## メニューとマップ

ヘッダーの≡ボタンでメニューを開く。メニューからマップ、表示言語、日本語／Englishを選べる。メニューまたはマップを開くと、プレイヤー、敵、音の寿命などゲーム時間に属する処理を一時停止する。Escapeはメニューを開閉し、マップ表示中はマップを閉じて再開する。

マップは同じ正方形領域に重ねて表示し、閉じるかEscapeで戻る。訪問済みの床セルと、その場所から分かる壁・扉だけを描く。プレイヤー位置は連続座標から決め、矢印は無段階の向きを示す。敵は現在の検知情報だけで表示し、未訪問の床・壁情報は公開しない。扉マーカーには開閉状態を反映する。

ゲームオーバー後は移動、視点、Aボタン、敵行動を止める。メニュー、マップ、言語切り替えは使える。

## スマートフォン操作

操作エリアは画面下部に置く。左下の仮想スティックで前後移動と左右平行移動を行い、右下のAボタンで扉を開閉する。その他のコマンドボタンやページ切り替えUIは置かない。

スティックは半径に対する傾きで速度を決め、12%のデッドゾーンを持つ。斜め入力は単位長さに制限し、指を離すと即時停止する。指が表示範囲を出た後も、同じpointerIdのままスティック入力を続ける。壁と閉じた扉には円形の当たり判定を使い、軸ごとの移動で壁沿いに滑らせる。

スティックとボタン以外では、ゲーム画面、ステータス、ログ、空いている操作エリアから横方向の視点ドラッグを始められる。左ドラッグは左回転、右ドラッグは右回転、縦ドラッグは無視する。感度は `src/controls.ts` の `POINTER_TURN_RADIANS_PER_PIXEL` で調整する。初期値は190pxほどのドラッグで約180度回る。慣性は付けない。

入力開始時に決めた操作種別は、そのpointerIdを離すまで固定する。視点操作中の指がAボタンへ移動してもAは動作せず、A操作中の指が他の領域へ移動しても視点回転は始まらない。Pointer Eventsを使い、移動、視点、Aボタンを指ごとに管理する。`pointerup`、`pointercancel`、ウィンドウのblur、タブ非表示、メニュー表示時に入力を消去する。ブラウザーのスクロール・拡大操作は `touch-action: none` とviewport設定で抑える。

## PC操作と言語

スマートフォンと同じゲーム処理を使う。

- WASD：前後左右へ移動
- マウスドラッグ：水平方向の視点回転
- EまたはSpace：正面の扉を開閉
- Escape：メニューを開く／閉じる

メニューの言語ボタンで日本語と英語を切り替える。位置、敵、扉、探索済みセル、検知、ログ履歴は同じゲーム状態を使う。

## ブラウザと一時停止

`requestAnimationFrame` で更新と描画を進める。1回のシミュレーション更新は最大0.05秒に制限し、描画やタブ復帰で経過時間をまとめて進めない。タブを非表示にしたときと、復帰した最初のフレームは入力を消去する。

ブラウザテストは320、375、390px、PC幅、縦横画面、模擬Safe Area、正方形維持、ページスクロール、スティック／ドラッグ／複数指、Aボタンとの判定分離、メニューとマップの一時停止を確認する。実際のiPhone Safari、ノッチ、アドレスバー変化は未検証。
