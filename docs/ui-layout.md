# スマートフォン向けターミナルUI仕様

## 1. 目的と適用範囲

スマートフォンを主要な表示対象とするゲームUIの共通ルールを定める。今後のメニューやゲーム機能の追加時にも参照する。

本書は `src/main.ts`、`src/style.css`、`index.html` の現行実装と決定済みの設計方針に基づく。共通仕様、現在の実装値、サンプルデータ、未実装の設計方針を区別して記載する。移動方向の選択は設計方針であり、現行UIには実装されていない。

## 2. 画面構成と基本方針

ターミナル風の画面を縦方向に使用し、上から次の3領域で構成する。

1. ログ表示領域
2. 選択肢領域
3. ページナビゲーション領域

ページ全体はスクロールさせず、ログ表示領域だけを縦スクロール可能にする。選択肢とページナビゲーションは画面下部に残す。

画面高には `100dvh` を使用し、スマートフォンのブラウザのアドレスバー表示状態に追従する。Safe Areaを考慮し、viewportには `viewport-fit=cover` を指定する。

現行実装は縦方向のFlex配置。`100vh` をフォールバックとして記述した後に `100dvh` を指定し、四辺の余白は `max(16px, env(safe-area-inset-*))` で確保している。`html`、`body`、`#app` は `overflow: hidden`。

## 3. ログ表示領域

- 選択肢領域とページナビゲーションを除いた残りの高さをすべて使用する。
- ログ量が増えた場合は、ログ領域内部だけを縦スクロールする。
- 新しいログを追加した場合は末尾を表示する。
- 長い日本語文章も折り返して表示する。
- ログと操作UIのスクロールを分離する。

現行実装は `flex: 1`、`min-height: 0`、`overflow-y: auto`。`overscroll-behavior-y: contain` でスクロールの伝播を抑制する。ログ行には `white-space: pre-wrap` と `overflow-wrap: anywhere` を使用し、追加時は `scrollTop = scrollHeight` で末尾を表示する。

### プレイヤー入力と入力待ち（共通仕様）

- 操作待ちではログ末尾に `>` を1つだけ表示する。通常選択肢が無効でも、戻るなどの操作が可能なら入力待ちとする。完全に操作不能なら表示しない。
- サブメニューを開いただけでは入力を確定せず、末尾の `>` はそのまま表示する。最終的な操作対象を選んだ時点で、選択経路を半角スペース区切りで `> 操作名 対象名` の1行にまとめて確定する。その場で完了する操作は即時確定する。
- 入力確定後は必ず空行を1行挿入し、その後にゲームシステム・AIの出力を表示する。次の操作待ちで新しい `>` を追加する。
- 入力経路の例：`> 監視 居住区`、`> 移動 医療区`、`> 設備 帰還船へ配電する`、`> 持ち物 食糧`、`> 逃げる 医療区`。将来の複数階層も `> 操作 サブ操作 対象` として同じ規則で記録する。
- ボタン表示と入力履歴用ラベルを分離できる構造とする。入力行には簡潔な選択肢名を使用し、ボタン末尾のメニュー遷移記号 ` >`、方面などの補足、補足行（成功率・ENERGY・監視情報）は含めない。
- `戻る`・`＜`・`＞` はUIナビゲーションなので入力ログに記録せず、空行やプロンプトも追加しない。
- `戻る` でサブメニューを離れると、その階層で追加した未確定入力を破棄する。ページ送りは未確定入力を変更しない。同じサブメニューで続けて対象を選ぶ場合は、その画面の選択経路を使用する。
- 開始画面、GAME CLEAR／GAME OVER後も同じ規則を適用する。ゲーム開始・最初からの入力を残し、ゲーム状態を初期化した後の導入出力へ続ける。

```text
> 状態確認

LOCATION : 居住区
ENERGY : 18 / 20
>
```

現行実装では `pendingInput` 配列が未確定の選択経路、`Option.submenu` がメニュー遷移、`Option.inputLabel` が表示と異なる履歴用ラベルを管理する。`appendImmediate()` が即時出力、`appendLog()` がゲーム／AI出力のキュー追加、`showPrompt()` が入力待ちの管理、`confirmInput()` が入力確定と空行の即時追加を担当する。入力待ち行は要素参照で管理し、再描画やナビゲーションで重複させない。

### タイプライター表示・操作制御（共通仕様）

- プレイヤー入力履歴と直後の空行は選択確定時に即時表示する。入力文字には演出を適用しない。
- ゲーム／AI出力は1文字ずつ表示する。初期画面、導入、状態確認、移動・監視・遭遇結果、ENERGY増減、GAME OVER／GAME CLEARも同じ方式とする。
- 仮速度は5ms／文字。`TYPEWRITER_INTERVAL_MS` にまとめ、プロトタイプの調整値として扱う。完成版仕様として固定しない。
- 複数行は行順を維持し、各行を完成させてから次の行へ進む。複数回の出力呼び出しも同じキューへ順番に追加する。
- 全出力完了後に操作待ちの `>` を1つだけ表示する。表示途中には表示しない。
- 共通状態 `isTyping` により、通常選択肢・サブメニュー・遭遇対処・ゲーム開始・最初からを無効化する。戻る・＜・＞・HELPも無効化し、既存の配置は維持する。共通クリック処理でも表示中の実行を拒否する。
- 表示終了後に現在メニューから本来のdisabled状態を再計算する。CLOSED移動先、完了済み設備、未達成条件の発進などは通常時は無効、HELP ONでは参照可能にする。
- タイプ表示中にログ領域をタップ／クリックすると、表示中の行の残りとキュー全体を元の順序で即時表示する。専用スキップボタンは追加しない。
- スキップはタイマーを停止し、途中状態・キューを消去してから操作を復帰させる。文字・行・プロンプトの二重表示、タイマー残存、ゲーム処理の二重実行を防ぐ。表示終了後のログ連打は何も実行しない。
- 再開始時もタイマー・キュー・文字位置を初期化し、即時表示の `> 最初から` と空行に導入出力を続ける。
- `prefers-reduced-motion: reduce` の場合はゲーム／AI出力も即時全文表示する。ログ順、空行、入力履歴、プロンプトは通常時と同じ。設定が表示途中にreduceへ変わった場合も残りを即時表示する。
- 表示中は最新文字へ自動スクロールする。現行実装は5msの文字更新に合わせて末尾へ追従する。ログに `aria-busy` を設定し、出力完了をまとめて通知する。
- ゲーム状態更新は入力時に従来どおり行い、表示タイミングのみを制御する。ゲームロジックの消費・進行・判定は変更しない。

## 4. 共通の選択肢レイアウト

- 基本レイアウトは2列×3行、1ページ最大6選択肢とする。
- ボタンの位置と大きさを可能な限り一定にし、最低高さ44pxを確保する。通常選択肢も下部ナビゲーションと同程度の高さを基本とする。
- ログ表示領域を優先して広く確保し、複数行の補足情報で選択肢領域全体を膨らませない。
- スマートフォンでタップしやすいサイズとし、ボタン間隔は現行実装を基準に8pxとする。
- 空き枠があっても選択肢領域全体の高さを変えない。
- 空き枠は押せるボタンにせず、操作を割り当てない。
- メニューごとの特殊な配置より、2列×3行の共通ルールを優先する。

現行実装はCSS Gridで、列を `repeat(2, minmax(0, 1fr))`、行を `repeat(3, 44px)` とする。空き枠も44pxの非表示 `span` として寸法を確保する。選択肢名は13px・行高13px、上下余白は各2px。選択肢は原則として操作名・対象名のみ表示する。ENERGY、成功率、通路状態、敵情報、情報の鮮度はボタンへ詰め込まずHELPログで参照する。操作不可はdisabledで示す。狭幅・低い画面でも行高は44pxを維持する。

## 5. 選択肢とメニュー遷移の表示

ラベル末尾の ` >` は、**2列×3行の通常選択肢を押すと別の選択肢メニューへ進む**ことを表す。

| 操作の種類 | 表示例 |
| --- | --- |
| 別の選択肢メニューへ遷移する | `持ち物 >` |
| その場で処理が完了する | `周囲を見る`、`状態確認`、`待機する` |

- `[実行]` などの追加文字列は使用しない。
- `>` がないこと自体を、その場で実行される操作の表現とする。
- 将来サブメニューが実装された項目には、その時点で `>` を付ける。
- サブメニュー化する予定があるだけでは付けない。現在実際にメニュー遷移するかどうかを基準にする。
- 下部ナビゲーションの `戻る`、`＜`、`＞` はこの表示ルールの対象外。

現行実装は `{ label, hasNext }` と `actionLabel()` で表示を生成する。`hasNext` の仕様上の意味は「別の選択肢メニューへの遷移があるかどうか」であり、将来の候補の有無ではない。ナビゲーションの「戻る」は `actionLabel()` の対象とせず、記号を付けない。

## 6. ページナビゲーション

選択肢6枠とは別の下部領域に、常に次の5要素を1行で表示する。戻るは左端に固定し、`＜`・ページ番号・`＞` は1つのページ操作グループとして画面中央付近に配置する。単純な5列均等配置にはしない。

```text
[戻る]   [＜]   1 / 2   [＞]   [HELP]
```

すべての選択肢画面で表示し、1ページしかない場合も `1 / 1` とする。

| 状態 | ＜ | ＞ |
| --- | --- | --- |
| 1ページのみ | disabled | disabled |
| 複数ページの最初 | disabled | enabled |
| 中間ページ | enabled | enabled |
| 複数ページの最後 | enabled | disabled |

- `＜` は前ページ専用、`＞` は次ページ専用とし、途中で意味を変更しない。
- 画面やページが切り替わっても位置を動かさない。
- disabled時も位置・サイズを変えず、状態を視覚的に示す。
- ページ切り替えと戻る操作ではログを追加しない。
- 通常の選択肢と同程度の高さとし、最低44pxのタップ領域を確保する。
- 「戻る」は左端の専用ボタンとし、親メニューがある場合のみenabledにする。
- 戻るは前後ボタンより横幅を広くし、将来 BACK 等の英語表記でも余裕を持って表示できる幅を確保する。
- ページ番号は48px前後の安定した幅を確保する。
- 戻るの文字幅が変わってもページ操作グループの中央位置をできるだけ維持する。狭い画面では重なりを避け、1行に収まることを優先する。

現行実装は `action-navigation` を1fr / auto / 1frの3列Gridとし、左端に幅52pxの戻る、中央にページ操作、右端にHELPを配置する。前後ボタンは44px、ページ番号は48px、ページ操作内gapは8px、外側gapは4px。HELPも最低44pxのタップ領域を確保し、320px幅（左右16px余白）に収める。

## 7. 誤操作防止

ページ操作ボタンを同じ位置の別の意味の操作へ変更しない。特に `＞` を最終ページで「戻る」などに変更してはならない。`戻る` は常に親メニューへ戻る、`＜` は常に前ページ、`＞` は常に次ページであり、disabled時も位置を維持する。ページ送りと戻るは別の固定ボタンとする。

ページ送りとゲーム上の選択肢は別領域にし、連打によって意図しないゲーム操作が実行されない構造にする。この固定ルールはページ操作に対するものであり、グリッド内の項目自体はページごとに切り替わる。

以前の試作では「次へ」を連打すると、最終ページで同じ位置が「戻る」に変わり、さらに通常メニューの別操作まで押してしまう可能性があった。この問題を避けるため、現在の固定ナビゲーション方式を採用した。

現行実装は前後ボタンの要素を維持し、ページ境界ではdisabledにする。クリック処理にもページ境界の確認があり、最終ページで次ページ操作を繰り返しても別の操作へ移行しない。

## 8. 「戻る」の扱い

- 通常選択肢6枠には含めず、下部ナビゲーションの左端に固定配置する。
- 表示は `戻る` とし、`>` を付けない。
- 親メニューがある画面ではenabled、最上位メニューではdisabledにする。
- どのページからでも親メニューへ戻れる。
- 戻る操作そのものはログに追加しない。
- disabled時も位置とサイズを変えず、最低44px程度のタップ領域を確保する。
- ページ数には影響しない。対象選択画面では通常選択肢のキャンセルも枠とページ数に含む。

現在の持ち物画面では、どちらのページからでも通常メニューへ戻れる。具体例は「12. 現在の画面例」に示す。

## 9. ページング

- 1ページ最大6選択肢とし、7個以上ある場合はページ分割する。
- ページ間で選択肢領域のサイズを変えない。
- 最終ページに項目が少なくても空き枠で高さを維持する。
- 空き枠には操作を割り当てない。
- ページ送りには下部の共通ナビゲーションを使用する。

現行の持ち物は10アイテムを2ページ（6アイテム、4アイテム）に分割し、最終ページの残り2枠を操作できない空き枠にする。戻るはナビゲーションに配置し、ページ数に影響しない。アイテム数・名称はレイアウト確認用のサンプルであり、共通仕様として固定するものではない。

## 10. 移動方向の選択肢（設計方針・未実装）

前・後ろ・左・右などの方向選択でも、実空間を模した十字配置は採用しない。

採用しない配置例：

```text
      前
左          右
      後ろ
```

十字配置は2列×3行と相性が悪く、空き枠や例外処理が増える。左右の見た目が不均衡になりやすく、他のメニューと操作体系が変わってしまう。

共通レイアウトを維持し、意味的に対になる操作を同じ行へ配置する。

```text
[前へ]       [後ろへ]
[左へ]       [右へ]
[補助操作]   [空き]
```

4方向しかない場合も、基本的に1行目は前／後、2行目は左／右の順序とする。補助操作の内容は未定であり、この図は配置方針を示す。戻るはグリッド外の共通ナビゲーションを使用する。空間的な十字配置より、同じ種類の操作を常に同じレイアウト規則で表示することを優先する。各方向操作の `>` の有無は、実際のメニュー遷移の有無に従う。

## 11. デザインとアクセシビリティ

### デザイン

| 項目 | 共通方針・現在の実装値 |
| --- | --- |
| 外観 | ターミナル風、暗い背景 |
| 基本文字色 | `#4ade80`（ボタンも継承） |
| 枠線 | `#2f7548` |
| 背景色 | 現行実装値 `#0b0d0b` |
| フォント | 等幅フォント |
| ナビゲーションのサイズ・配置 | 左端の戻るを前後ボタンより広くし、独立したページ操作グループを中央付近に置く。実装値は第6章参照 |
| 選択肢の文字位置 | 現行実装は左揃え |
| 押下状態 | 背景 `#1b281b`、枠線 `#4ade80` で示す |
| disabled状態 | 現行実装は `opacity: 0.4` で示す |

過度な発光・ネオン効果は使用しない。選択肢の押下状態とdisabled状態は視覚的に判別できるようにする。

### 現在実装されているアクセシビリティ・スマホ操作

以下は現行実装に存在する対応である。

| 対象 | 実装内容 |
| --- | --- |
| ログ | `role="log"`、`aria-label="ゲームログ"`、`tabIndex = 0` |
| 選択肢領域 | `role="group"`、通常は `aria-label="行動を選択"`、持ち物ではページ情報を含むラベル |
| ナビゲーション | `nav`、`aria-label="選択肢のページ操作"` |
| 戻るボタン | `aria-label="親メニューへ戻る"`、親メニューがない場合はdisabled |
| 前後ボタン | `aria-label="前のページ"`／`"次のページ"`、ネイティブbuttonのdisabled |
| ページ番号 | `aria-live="polite"` |
| 空き枠 | `aria-hidden="true"`、非表示spanであり操作不可 |
| キーボードフォーカス | 選択肢・ページボタン・ログに `:focus-visible` のアウトライン |
| 画面遷移時のフォーカス | 持ち物を開くと最初のアイテムへ、戻ると通常メニューの持ち物へ。`preventScroll: true` を使用 |
| タッチ | 選択肢とページボタンに `touch-action: manipulation` |
| タップ領域 | 選択肢・空き枠は高さ44px、戻る・ページボタンは最低44px×44px |
| 画面端 | 四辺のSafe Areaを考慮 |
| viewport | `width=device-width, initial-scale=1.0, viewport-fit=cover` |

未実装の支援機能は本書で追加仕様として定めない。

## 12. 現在の画面例（サンプル実装）

以下の項目名と個数は現行サンプルの具体例であり、共通仕様ではない。

### 通常メニュー

```text
[周囲を見る]   [扉を調べる]
[端末を調べる] [持ち物 >]
[状態確認]     [待機する]

[戻る disabled]   [＜ disabled]   1 / 1   [＞ disabled]
```

通常メニューでは「持ち物 >」だけが別メニューへ遷移する。最上位なので下部ナビゲーションの「戻る」はdisabled。他の5項目は現時点では選択した名前をログに追加するだけである。

### 持ち物：1ページ目

```text
[非常用ライト] [古い鍵]
[メモ]         [ドライバー]
[IDカード]     [電池]

[戻る]   [＜ disabled]   1 / 2   [＞]
```

### 持ち物：2ページ目

```text
[小型端末]     [ヒューズ]
[薬品ボトル]   [ケーブル]
[空き]         [空き]

[戻る]   [＜]   2 / 2   [＞ disabled]
```

「空き」は説明上の表記で、画面には文字もボタンも表示しない。10アイテムのどれにも現在はサブメニューがなく、`>` を付けない。アイテムを押すと名前だけをログ末尾へ追加する。アイテム使用・対象選択のゲームロジックは未実装。

「持ち物 >」を開くたびに1ページ目を表示する。ページ操作と `戻る` ではログを追加しない。`戻る` は通常メニューへ遷移する。

## 13. 今後の拡張ルール

調査対象、会話選択肢、アイテム使用先、移動先、その他のサブメニューが増えても、原則として次の共通ルールを再利用する。

- 2列×3行、1ページ最大6選択肢
- 常設の共通ページナビゲーション
- `>` による実際のメニュー遷移の表示
- 下部ナビゲーション左端の固定された `戻る`
- ページ送りの位置と意味の固定

個別画面ごとに独自UIを追加する前に、この共通ルールで表現できないか検討する。現在のサンプルデータやログ追加のみの処理を、将来のゲームロジックの仕様として扱わない。

## 14. HELP参照モード

- 選択肢は原則として操作名・対象名のみ表示する。ENERGY、成功率、通路状態、敵情報などの詳細は常時ボタンに詰め込まずHELPログで表示する。
- 下部右端に常設のHELPトグルを置く。表示文字列は常に `HELP`。OFFは通常ボタン、ONは背景 `#4ade80`・文字 `#0b0d0b`・枠線 `#4ade80` の反転表示とする。通常の一時的な押下表示とは区別する。
- `aria-label="HELPモード"` と `aria-pressed="true" / "false"` で状態を伝える。切り替え自体はログ追加・ENERGY消費・ターン進行を伴わない。
- HELPはUI設定 `helpMode` として保持する。メニュー・ページ遷移、キャンセル、HELP参照、最初からでも保持する。
- HELP ONで移動先、監視対象、設備、遭遇対処、持ち物を押すと実行せず説明する。CLOSEDや完了済み設備もHELPでは説明を参照できる。逃走は対象区画のHELPで成功率100%と通路コストを説明する。
- 入力履歴は `> HELP 操作名 対象名`。対象のない対処は `> HELP 隠れる` などとする。通常履歴 `> 移動 居住区` とは明確に区別する。
- HELP入力と空行は即時表示、本文は5ms／文字の既存タイプライター、ログタップでスキップ可能。本文表示中はHELPを含む全ボタンを無効にし、完了後も元のHELP設定を維持する。
- 本文表示後は元の選択メニュー・ページ・未確定入力経路に留まる。HELP OFFにして選択すると通常実行する。
- HELPは完全な参照操作。`game.act()`・乱数処理を呼ばず、ゲーム状態と既存の読み取り専用メソッドから説明を生成する。ENERGY、ターン、現在地、通路・通路変化、敵・直前位置、遭遇・判定、監視情報・鮮度、アイテム、タスク、補給使用済み、帰還条件、終了状態、乱数状態を変更しない。
- 移動HELPは既存の監視情報と鮮度、現在無料で分かるCLOSEDのみを説明する。未監視の通路状態・敵・正確なコストはUNKNOWN／未確認とし、コスト範囲1〜3のみ示す。古い情報は現在の安全性を保証しない。監視HELPでは新しい監視を取得しない。
- 対象選択画面には通常選択肢として `キャンセル` を追加する。履歴は経路を付けず `> キャンセル`。親メニューへ戻り、ENERGY・ターン・世界・敵・鮮度を変更しない。HELP ONでも通常キャンセルとして扱う。下部の戻るは引き続きログを追加しない。
