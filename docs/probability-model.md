# 観測と成功確率

この文書は内部ルールを定義します。選択肢には、現在までの観測から推定した整数の成功率を表示します。隠れた区画状態や丸める前の確率は画面へ出しません。

## 隠れた区画状態

各区画は開始時に50%ずつの確率で「安定」「劣化」になります。状態は5マスの区画内で固定です。区画ごとに独立し、同じ状態が連続することもあります。

## 観測

各イベントは区画の状態に応じて、次のいずれかの観測を抽選します。文章はイベントごとに異なりますが、尤度は共通です。

| 観測の種類 | 安定時 | 劣化時 |
| --- | ---: | ---: |
| 安定した値・動作 | 0.62 | 0.15 |
| 断続的な警告・異音 | 0.28 | 0.45 |
| 電圧低下・異常ログ | 0.10 | 0.40 |

どの観測も両方の状態で起こり得ます。ひとつの説明だけで状態が確定することはありません。同一区画で得た観測は、固定された状態を条件として各イベントで独立に抽選されます。

## 成功率の算出と判定

各行動には基準値 `baseChance` と状態補正 `stableModifier` があります。

```text
安定時の成功確率 = clamp(baseChance + stableModifier, 0.08, 0.92)
劣化時の成功確率 = clamp(baseChance - stableModifier, 0.08, 0.92)
```

観測から得た安定状態の事後確率を `q` とし、行動の安定時・劣化時の成功率を `p_stable`、`p_degraded` とすると、表示前の推定成功率は次のとおりです。

```text
推定成功率 = q × p_stable + (1 - q) × p_degraded
表示率 = round(推定成功率 × 100)
```

この整数値を選択肢と行動ログに表示し、スロット判定にもそのまま使います。停止数字を `n` とすると `n < 表示率` の場合だけ成功です。たとえば65%なら00〜64が成功、65〜99が失敗です。丸める前の確率や隠れた区画状態はDOMへ出力しません。

## 観測と履歴からの推測

事前確率は各区画50%です。同一区画で観測を得るたび、安定状態での確率をベイズ則で更新します。状態 `s` の尤度は観測の積です。

```text
P(s | 観測) ∝ P(s) × Π P(o | s)
```

現在イベントの観測も選択前の推定に使います。スロット結果は表示済み成功率と乱数数字だけで決まるため、設備状態の証拠にはなりません。そのため成功・失敗履歴は状態推定に使いません。過去の観測と行動結果はログに残り、区画番号を見て同じ区画内の観測を追えます。実装では `inferStableProbability()` と `estimateSuccessProbability()` が推定し、`successProbabilityPercent()` が整数へ丸めます。

## 乱数と再現

ゲームの施設状態・観測・イベント抽選には `RandomSource` を使います。確定したスロット数字はゲーム処理へ整数00〜99として渡し、ゲーム側は同じ表示率との比較で結果を確定します。画面上の数字更新には別の乱数源を使うため、回転時間はゲームの乱数列や次イベント抽選に影響しません。テストでは停止数字を指定でき、同じ状態・行動・数字から同じ結果を再現できます。開発時は `?seed=12345` のようにURLでゲームシードを指定できます。通常のランでは新しいシードを作り、画面には表示しません。
