# 画面と操作

## 表示

画面を3領域に分け、黒背景、緑文字、等幅フォントのコンソールとして表示します。上部の固定ステータスには `EXIT SEQUENCE`、現在位置（`03 / 15` の形式）、現在の電力（`15 / 20` の形式）を表示します。中央のログが残りの高さを使い、下部の選択欄は画面下に固定します。ログにはイベント、説明、観測、行動履歴、結果を時系列で追加します。位置と現在電力は上部に表示するため、ログへ重複して出しません。行動結果による電力の増減と上限・下限の補足はログに残します。

新しく追加するログは基本10msごとに1書記素ずつ表示します。表示済みログを再アニメーションしません。ログはランの間保持され、中央の領域だけを縦にスクロールして確認できます。プレイヤーが末尾付近を見ている場合は新しい文字に合わせて自動スクロールし、過去ログを読んでいる場合は位置を保ちます。「最新ログへ」で末尾に戻れます。

行動の成功率、隠れた区画状態、乱数シードは表示しません。選択肢には既存の行動名・説明と、成功・失敗時に適用される電力差分を表示します。

## 文字送りと入力

| 操作 | PC | スマートフォン |
| --- | --- | --- |
| 文字送りをスキップ | コンソールをクリック、`Space`、`Enter` | コンソールをタップ |
| 行動を選択 | 選択肢をクリック、または `1`・`2`・`3` キー | 選択肢の行をタップ |
| 最新ログへ戻る | 「最新ログへ」をクリック | 「最新ログへ」をタップ |
| 終了後に再挑戦 | 再スタート行をクリック | 再スタート行をタップ |

選択待ち中はログ末尾の `>` の後ろに点滅カーソルを表示します。行動を選ぶと同じ行に番号と行動名を文字送りして確定し、表示完了後に結果を出します。選択した入力は過去ログとして保持します。次のイベントでは新しい `>` 行を追加します。下部の選択欄にプロンプトやカーソルは表示しません。

出力中は選択肢を無効にし、表示が終わった後に入力を受け付けます。スキップは待っている文字の表示だけを完了し、行動、乱数判定、電力消費、イベント進行を行いません。PCの数字キーは選択肢が有効な間だけ使えます。`prefers-reduced-motion: reduce` が有効な場合は文字送りを省略し、全文を即時表示します。非表示タブでは出力を一時停止し、復帰時に続きから再開します。

出力待ちテキストはゲームロジックと分離したキューで順番に処理します。選択履歴の確定と行動判定も分け、行動名の文字送りが終わってから判定を実行します。文字の追加ごとにログ領域全体を作り直さず、スクリーンリーダーには文字単位の大量通知を送らない設定です。再スタート時は旧キューとカーソルを消し、ログを消去して新しいランを始めます。

## レスポンシブ対応

幅320px以上のスマートフォン縦画面を優先し、横スクロールなしで長い日本語を折り返します。上部ステータスと下部コマンド選択はGridの固定行に配置し、中央ログだけを残りの高さで縦スクロールさせます。入力欄は高さを制限して内部スクロールを持ち、ログ出力中も位置を保ちます。選択肢のタップ領域は高さ44px以上です。iPhoneのSafe Areaを反映し、PCでは最大幅760pxで中央に配置します。

ブラウザテストは320×640、390×844、1280×800、812×375で、ステータス・ログ・入力欄の実測位置、領域同士の重なり、画面外にはみ出す選択肢、幅・高さ超過を確認します。タップ、マウス、数字キー、ログのスクロール、文字送りのスキップ、Reduced Motion、再スタートも操作します。テストのChromiumはブラウザ自動化による確認です。実機のiPhone SafariやAndroid端末では検証していません。
