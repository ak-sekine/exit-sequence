# 画面と操作

## 表示と配色

画面は上部の固定ステータス、中央のログ、下部の入力欄の3領域です。背景は黒系、文字は本文、ステータス、選択肢、成功率、電力差分、カーソル、「最新ログへ」、再スタートまで濃い緑 `#4fd66a` に統一しています。成功・失敗・クリア・ゲームオーバーも色を変えず、ログの文言で区別します。枠線とホバー背景には暗い緑を使います。

上部には左に現在位置、右に電力だけを横並びで固定表示します。固定タイトルと固定イベント画像は置きません。`EXIT SEQUENCE` はラン開始時のログ先頭に1回表示します。位置と電力の文字サイズは16pxで、ステータス領域の高さと上下余白を最小限にします。

10イベントそれぞれに、既存のローカルSVG設備画像を1点ずつ対応させます。画像は `[EVENT]` 見出しの直後に独立したログ要素として挿入し、その後に説明と観測を出力します。画像はイベント発生ごとに追加し、過去の画像を置き換えません。最大幅320px、比率8:5で左揃えにし、スマートフォンではログ幅に合わせて縮小します。画像読み込み前から比率に応じた表示領域を確保し、読み込みエラーでも後続の説明・観測・操作を続けます。

基本の文字サイズは、位置と電力16px、ログ本文15px、選択肢の行動名15px、成功率と電力差分14px、スロット数字28px、「最新ログへ」14px、再スタート15pxです。画面幅や高さが小さい場合も通常UIの文字サイズを14px未満にはしません。

中央ログはイベント見出し、画像、説明、観測、選択履歴、結果を時系列に追加し、位置と電力は上部にだけ表示します。テキストは基本10msごとに1文字ずつ表示し、画像は見出しの後に即時追加します。スキップ時も画像は各イベントにつき1回だけ追加します。表示済みのログDOMは再生成せず、ログはランの間保持されます。中央の領域だけを縦にスクロールして読み返せます。末尾付近を見ている場合は新しい内容に合わせて自動スクロールし、過去ログを読んでいる場合は位置を保ちます。画像読み込み完了ではスクロール位置を変えません。「最新ログへ」で末尾に戻れます。

下部には見出しを置かず、3つの選択肢を1行ずつ表示します。行動名・推定成功率・成功時と失敗時の電力差分を1行に並べ、例として `[1] 制御系から再起動 65% +5/-4` の形式で表示します。成功率は整数で、不要なゼロ埋めはしません。選択肢と電力差分はイベント画像・ログの表示中も即時に表示し、中央ログの出力が終わるまで操作を無効にします。説明文と `[SELECT ACTION]` は表示しません。行動名を省略せず、320px幅でも各行44px以上のタップ領域を保ちます。選択待ちになるとログ末尾に `>` とカーソルを出します。

## 文字送りと入力

| 操作 | PC | スマートフォン |
| --- | --- | --- |
| 文字送りをスキップ（通常ログ中） | コンソールをクリック、`Space`、`Enter` | コンソールをタップ |
| スロットを停止 | 画面をクリック、`Space`、`Enter` | 画面をタップ |
| 成功・失敗結果の後に次へ進む | 画面クリック、`Space`、`Enter`、または「次へ進む」 | 画面タップ、または「次へ進む」 |
| 行動を選択 | 選択肢をクリック、または `1`・`2`・`3` キー | 選択肢の行をタップ |
| 最新ログへ戻る | 「最新ログへ」をクリック | 「最新ログへ」をタップ |
| 終了後に再挑戦 | 再スタート行をクリック | 再スタート行をタップ |

行動を選ぶとログ末尾の `>` と同じ行へ番号と行動名を文字送りして確定し、続けて選択肢と同じ成功率を表示します。`[ROLL] 00`〜`[ROLL] 99` の数字は50msごとに同じDOM要素内でランダムに切り替わります。画面タップまたはクリック、PCの `Space` または `Enter` で停止し、表示中の数字を確定します。確定数字が成功率未満なら成功です。判定後の `[ROLL]` はログ履歴に残り、結果ログと次イベントの説明は10ms文字送りを続けます。選択した入力も過去ログとして保持します。次のイベントでは新しい `>` 行を追加します。下部の選択欄にはプロンプトやカーソルを表示しません。

成功・失敗どちらでもゲームが続く場合、結果を全文表示した後に一時停止し、下部の142px入力欄を高さ44px以上・文字サイズ15pxの「次へ進む ▶」ボタンに切り替えます。画面内をタップ・クリックするか、ボタンを操作すると次イベントをログ末尾に追加します。結果文字送り中のタップ・クリックは文字のスキップだけに使い、進行には別操作が必要です。待機中は確定したスロット数字、成功・失敗ログ、反映済みの電力、現在のPOSITIONとイベント画像を維持し、次イベントの画像や選択肢は表示しません。タップ待ちの制限時間はありません。脱出成功と電力切れでは進行ボタンを表示せず終了します。

通常ログの文字送り中のタップ・クリックは文字送りをスキップします。スロット回転中はタップ・クリックが停止操作になり、ログスクロールは停止として扱いません。停止に使った操作を次イベントの進行には再利用しません。結果の文字送り中はスキップ、全文表示後は進行操作として入力状態を切り替えます。二重入力は1イベント分だけ進み、ログスクロールや「最新ログへ」では進行しません。数字キーは選択肢が有効な間だけ使えます。`prefers-reduced-motion: reduce` が有効な場合は通常ログの文字送りを省略し、スロットはランダムな数字を静止表示して停止操作を待ちますが、結果後の進行には別の操作が必要です。非表示タブではログと数字更新を一時停止し、復帰時に続きから再開します。

出力待ちテキスト・画像とスロット表示更新はゲームロジックと分離しています。イベントログは順序付きキューで処理し、画像は安全なDOM要素として追加します。選択履歴の確定、数字の停止、行動判定を順に処理し、確定数字をゲームへ渡します。数字が回転している間は同じテキストノードだけを更新し、ログ行は増やしません。スクリーンリーダーには更新中の数字を通知せず、確定数字と結果を読み上げます。再スタート時は旧キュー・スロットタイマー・カーソルを消し、ログを消去して新しいランを始めます。

## レスポンシブ対応

幅320px以上のスマートフォン縦画面を優先し、横スクロールなしで長い日本語を折り返します。短い上部ステータスの下に中央ログの表示領域を広く確保します。中央ログだけが縦スクロールし、3行の入力欄は142pxのコンパクトな固定高です。PCでは最大幅760pxで中央に配置します。

ブラウザテストは320×640、390×844、1280×800、812×375で、指定文字サイズ、配色、イベント画像10種の対応、見出し・画像・説明・観測の順序、画像の寸法確保、入力欄の高さ、領域同士の重なり、選択肢の文字切れ、横スクロールを確認します。タップ、マウス、数字キー、ログのスクロール、文字送りのスキップ、スロット停止、成功・失敗後の進行待ち、Reduced Motion、再スタートも操作します。テストのChromiumはブラウザ自動化による確認です。実機のiPhone SafariやAndroid端末では検証していません。
