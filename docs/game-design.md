# Exit Sequence ゲームデザイン（正本）

中心は、原因を当てることではなく、観察によって原因を発見し、理解したあとで対処を一段だけ考えること。

異常を見る → 追加観察 → 原因発見 → 必要ならAIのヒント → 対処 → 結果で因果を確認 → 次の問題。

損傷した月面基地から帰還船へ進む。認識系が異常なロボットは、人間を拘束しようとする強いアームによる危険と足音で、脱出の動機と緊張感を作る。ロボット攻略、準備スロット、資源消費、負傷、試行コスト、GAME OVERは今回の評価対象から外す。乱数、時間制限、自由入力、LLM、巨大な組み合わせは使わない。

3問題は圧力差の扉、氷が軸を止めるバルブ、二台同時使用で落ちる電源。知識があれば観察を短くでき、AIヒントは省略できる。ただし隠れた内部原因を外から当てる必要はない。氷はカバーを開けて現物を見せる。電源は一台と二台を比較する。扉は点検窓の力の矢印で、圧力が押し戻すことを見せる。

AIは3段階。事実の確認、場所と原因の説明、平易な原因と対処方向。早く説明を求めた場合も、第2ヒントで実際の点検描写を伴って原因画面へ進む。ヒントに罰も評価表示もない。最終ヒントはほぼ答えを伝えてよい。助けを使って理解し、進めることを優先する。

対処候補は原因を観察してから表示する。バルブではヒーターと工具、電源では不要装置停止と順番運転。普通の誤操作は原因を残し、何が変わらなかったかを示す。成功も原因の変化と動作を描く。均圧と開扉、加熱とレバー操作は別Choice。

15 Scene / 30 Choice定義。非終了画面は1～4行動。結果画面は次へ進む一つだけでよい。初見5～10分が目安で、実測ではない。緑のログUIと日本語・英語を維持する。

評価するのは、異常への疑問、現物からの原因発見、原因を理解した対処、知識ゼロでも進める説明、知識がある人の短縮、結果による因果確認。自動テストは成立条件を確認するが、面白さを証明しない。初見プレイヤーの発話とヒント利用段階を別途観察する。

## 開始時の前提と経路

パズルの原因を発見する前に、遊ぶための前提をwakeで伝える。主人公は月面基地の居住区で目を覚ます。窓に月面と黒い空が見える。基地は事故で損傷し、生命維持が不安定なため長く留まれない。通信と廊下への呼びかけに応答がなく、AIが現在確認できる生存者は主人公だけと伝える。他の人の居場所や生死、事故原因、ロボット異常の原因は断定しない。

地球へ戻る手段は別区画の帰還船。一本道は、居住区 → 非常隔壁 → 環境制御通路 → 帰還船ドック → 帰還船。途中の設備を復旧しながら向かう。異常なロボットは人間を作業員と認識せず、発見した相手を拘束しようとする。強いアームで負傷する危険があることをAIが明言する。戦闘・追跡・新しい終了条件は設けない。

新しい場所へ入ったときは、今いる場所・目的地・障害・解決する理由が文章から分かるようにする。居住区では非常隔壁を開けて通路へ出る。通路では送気バルブを開けてドックに空気を送り、空気不足で閉じた入口を通行可能にする。ドックでは目の前の帰還船の空気充填機を動かし、乗船準備を整える。解決結果と次への行動には、移動と帰還船への接近、背後の足音を短く添える。

CLEARは帰還船で月面基地を離れ、ロボットと損傷した基地を後にした安堵を描く。他の人を確認できなかった事実だけを伝え、生死と事故原因は未確定のまま残す。
