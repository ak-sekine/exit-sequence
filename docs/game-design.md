# EXIT SEQUENCE — 共通ルールの脱出ゲーム

中心の仮説は、**単純な共通ルールから複数の攻略法を作れるか**。少数のルールを知ったプレイヤーが、自分で組み合わせを見つけ「こんな方法でもクリアできるのか」と感じられるかを検証する。開発者の用意した正解Choiceを選ぶことは目的にしない。

8×8の盤面で @ を G に到達させる。要素は PLAYER / ROBOT / BOX / HOLE / GOAL / WALL だけ。移動と連鎖pushを全物体に共通で適用する。穴は物体を消し、出口は普通の床として扱う。ロボットは横を優先してプレイヤーへ近づき、同じpushで箱もプレイヤーも押す。プレイヤーが押されて出口へ入っても成功する。

人間の実プレイで、相互作用を使わず歩くだけでCLEARできる問題が判明した。ステージ設計原則を **相互作用は必須、利用方法は複数** とする。最短解だけでなく、到達可能な全状態から相互作用なしのCLEARが存在しないことを確認する。入力列やCLEAR終端状態の数を攻略方法の数とみなさない。迷路の延長や追加ギミックで解決しない。

3ステージだけを用意する。STAGE 1では通路の箱を退かすか消すかを発見してほしい。STAGE 2ではROBOTが押した箱とROBOT自身の位置を使って出口への通り方を作ってほしい。STAGE 3では同じ箱を押す動作でも、入る列を変えるとROBOTのpushを出口への移動に使えることを発見してほしい。ROBOTの消失、生存したままの利用、押されて出口へ入る方法が共通ルールから成立する。開始直後の↓↓ではCLEARできず、押されて出口へ入るにはPLAYER自身による位置変更が必須。攻略分類・探索・再現例はtestsと検証文書だけに置く。ゲーム画面は共通ルールだけを伝える。

ルールは初めから短く表示する。タップで即座に動き、失敗も成功もステージ開始までUNDOできる。RESTARTも常に使える。ペナルティより実験を優先する。

物語、戦闘、成長、装備、アイテム、報酬、スコア、時間・手数制限、乱数、追加ギミック、セーブ、バックエンドを入れない。手数はエンジンのターン検証用で、画面にスコアとして表示しない。

自動検証が示せるのは、ルールの一貫性、異なる攻略の存在、操作可能性まで。想定外の方法を思いついた感覚、自分で発見した感覚、別の方法を試したくなるか、単なるSokobanに感じないか、ロボットを道具として利用したくなるかは、人間の初見プレイによる評価待ち。
