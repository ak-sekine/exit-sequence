# Exit Sequence ゲームデザイン（正本）

## 中心となる体験

損傷した月面基地で、文章から世界の仕組みを理解し、その仕組みを利用して帰還船へ進む。主人公とサポートAI、一体のロボットを中心とした短いSFサバイバル。主人公の名前・性別・年齢・職業、事故の背景は確定しない。

**観察 → 危険と仕組みを読み取る → 必要な情報を集める → 攻略を考える → 準備 → 実行 → 結果を観察 → 改善して再挑戦。**

プレイヤーが組み合わせを考えることを中心にする。文章を読むことは判断の材料集めであり、最終的には別々の手段と操作を自分で組み合わせる。Choiceは行動を示し、成功の理由は書かない。Knowledge取得を正解ボタンの解禁に直結させない。

## 困難の単位

主な困難はロボット、壊れた気密設備、昇降台の電源とブレーキ、帰還船の発進。各困難は観察・準備・実行・結果の複数Sceneを持つ。結果まで進むためには、準備した内容を使う実行が必要。途中の追加観察、準備の変更、撤退、道具の回収ができる。

Sceneは場所の座標ではなく、現在の判断状況。Sceneデータに短い文章、条件付き描写、Choice、条件別の結果、次Sceneを記す。共通処理は条件と効果を適用する。特定の困難の攻略ルールをgame.tsへ書かない。通常2～5 Choice、消費済み道具などの条件によって減る場合がある。

準備は障害別の型付きスロットとして保持する。例えばロボットは光／箱／何もなしと、低い姿勢／静かな足場／直立を独立して選ぶ。情報・道具・準備・結果を区別し、個別booleanを増やさない。準備の変更は実行前なら自由だが、すでに消費した容器は戻らない。

## 観察と推論

ロボットの走査とアームは別に動く。光で一方を止めても、もう一方への対策が要る。気密設備は音がしても針が戻るなら完了ではない。昇降台は電源とブレーキの双方が必要。船は固定と均圧の関係、外部の線と逆流、青い準備灯から操作の条件を組み立てる。

危険は実行前に、見えるものと短い警告で予告する。観察Sceneは周期、関係、部品の位置を具体的に示す。記録端末は光と独立電源、長い音声は圧力と逆流の事例を提供する。どれも攻略順を自動実行しない。

危険な窓での観察は空気を使う。同じ観察を繰り返すと警戒も上がる。安全な札の再確認は許すが、情報・資源の取得を繰り返して得をすることはできない。読む現実時間ではStateは進まない。

## プレイヤーKnowledgeとゲームのKnowledge

内部Knowledgeは、実際に見た事実と記録の認識を保存する。既知の作業灯や電池の印を描写で結び付ける。過去ログのStateはコピーで保存し、後で得た理解を過去の文章へ逆流させない。

一方、プレイヤー本人の記憶にも攻略上の価値を持たせる。主要な準備と操作は未観察でも選べ、成功は実際の組み合わせから決まる。この縦切りではKnowledgeを行動表示・成功判定の条件に使わない。初見は現場と記録で情報を得られ、再プレイは記憶から短く準備できる。ゲームのセーブやKnowledge持越しはない。

## 複数攻略と成功の質

各困難に複数の方法を用意し、代償を変える。ロボットは光と低い姿勢、箱と静かな足場、低い姿勢と折返しの利用。気密は管を工具で修正、予備酸素で補助、漏れを待つ。昇降台は工具によるブレーキ解除、箱の振動、手動保持。船の外部切断は工具なら短時間、素手なら時間を使う。

内部結果はuntried / clean / costly / retreat / failure。UIに結果名や数値の表を出さず、呼吸、残った道具、痛み、物音と主人公の反応で質を表す。失敗後のより良い試行では、新しい負傷や空気の浪費を避けたことを描く。突破済みの設備を繰り返して資源や結果を取り直すことはできない。再プレイでは代償付き成功をより良い方法に改善できる。

## 失敗、撤退、再挑戦

多くの失敗は安全側へ戻る。結果文章には、止まった光、動き続けた腕、戻った針、点いた電源と残った爪など、原因を推測できる現象を残す。主人公が悔しがりながら観察し、AIは短く確認する。AIは次に押すボタンを教えない。

失敗の後も準備を解除して同じ困難へ再挑戦できる。事実・使える道具・痛み・空気・警戒は残る。撤退には時間と空気が要り、点検室から記録や未回収の道具を取りに行ける。初見の失敗を一度経験してもCLEARへ届く余地を持たせる。

無思考の総当たりは有利にしない。失敗には少量の空気、危険試行には負傷や警戒、箱と容器には一回の消費がある。同じ設備への3回目以降の試行は疲労で余分な空気を使う。繰返しの描写でそれを予告する。準備の組み替えや安全な表示確認自体を罰しない。

## OVERと最終問題

一度の普通の誤操作では即OVERにしない。空気の累積浪費、重い負傷後の追加負傷が主なOVER条件。明示された安全装置の封印を破る最終操作は即OVERにできる。

船は固定、均圧、外部切断、点火準備、点火を別々に操作する。票の図と現場表示から順序と依存関係を考える。外部切断と圧力操作の順序には自由がある。誤操作は警報と空気の代償を生むが、有効な準備を保持したまま直せる。解除すると均圧と点火準備は失われる。致命的な解除は赤い封印と明確な警告で区別する。

## 文章、UI、言語、範囲

児童文学くらいの読みやすさ、短く具体的な文章を維持。主人公は怖がり、強がり、軽口を言い、失敗に悔しがり、成功を喜ぶ。AIは正確で少し皮肉屋。日本語はAI：、英語はAI:。[writing-style.md](writing-style.md)に従う。

上はEXIT SEQUENCEと≡、中央は物語ログ、下は全幅一列の現在Choice。右上は言語設定のみ。緑色、320px、Safe Area、44px、typewriter、tap skip、reduced-motionを維持。状態・Item・Knowledge・マップの一覧は設けない。重要な判断前に準備と身体状態を文章で伝える。言語変更・メニュー・読書時間は非進行。ja/enで同じ条件・効果・Endingを共有する。

固定・deterministicな縦切りで、初見10～20分を目標とする。時間の大部分を観察・推理・試行に使う。人による所要時間と「自分で突破した」という感覚は別途プレイ評価が必要。乱数、リアルタイム操作、戦闘、HP、レベル、クラフト、方角移動、LLM、外部API、セーブ／ロードは追加しない。

評価は、情報を組み合わせる必要、独立した準備の意味、失敗原因の見え方、改善の余地、複数の方法、総当たりの代償、最後の操作を自分で組み立てた感覚の8点。実装と検証の具体例は[prototype-spec.md](prototype-spec.md)に記す。
